Eine **sichere Videokonferenz Checkliste** hilft IT, Datenschutz, Einkauf und Geschäftsführung, Anbieter nach denselben Kriterien zu bewerten. Entscheidend ist nicht die längste Funktionsliste, sondern ob Datenflüsse, Zugriffe und Verantwortlichkeiten nachvollziehbar belegt sind.

Dieser Leitfaden führt durch 25 Prüffragen. Bewerten Sie jeden Punkt mit **2 = erfüllt**, **1 = teilweise erfüllt**, **0 = nicht erfüllt** oder **n. a. = nicht anwendbar**. Notieren Sie neben der Bewertung immer den Nachweis oder die offene Frage. Die Liste ist eine Entscheidungshilfe und ersetzt weder Datenschutzberatung noch Datenschutz-Folgenabschätzung oder individuelle Risikoanalyse.

## Vor der Bewertung: Schutzbedarf festlegen

Beschreiben Sie zuerst, welche Gespräche über den Dienst laufen: interne Abstimmungen, Bewerbungsgespräche, Kundentermine oder Besprechungen mit besonders schützenswerten Informationen. Halten Sie außerdem fest, welche Metadaten, Chats, Aufzeichnungen, Transkripte und Exporte entstehen. Erst mit diesem Schutzbedarf lässt sich beurteilen, ob eine Maßnahme ausreicht.

Für die folgenden Vertrags- und Sicherheitsfragen sind insbesondere Art. 28 DSGVO (Auftragsverarbeitung) und Art. 32 DSGVO (Sicherheit der Verarbeitung) relevant. Beide Vorschriften verlangen eine risikogerechte Prüfung; sie schreiben nicht pauschal einen bestimmten Anbieter, Standort oder Verschlüsselungsstandard vor. [Beleg: DSGVO Art. 28 und 32](https://eur-lex.europa.eu/legal-content/DE/TXT/?uri=CELEX:32016R0679)

|---:|---|:---:|---|
| 1 | Ist dokumentiert, in welchen Ländern der Dienst betrieben wird? |  |  |
| 2 | Sind Speicher-, Verarbeitungs- und Supportstandorte getrennt ausgewiesen? |  |  |
| 3 | Ist eine aktuelle Liste relevanter Unterauftragnehmer verfügbar? |  |  |
| 4 | Gibt es einen passenden Auftragsverarbeitungsvertrag (AVV) mit klaren Weisungswegen? |  |  |
| 5 | Sind Änderungen bei Unterauftragnehmern und Widerspruchs-/Informationsprozesse geregelt? |  |  |
| 6 | Sind Drittlandübermittlungen und die dafür verwendeten Garantien nachvollziehbar dokumentiert? |  |  |
| 7 | Ist die Verschlüsselung der Übertragung dokumentiert? |  |  |
| 8 | Ist die Verschlüsselung gespeicherter Daten dokumentiert? |  |  |
| 9 | Ist erklärt, wie Schlüssel erzeugt, geschützt und gewechselt werden? |  |  |
| 10 | Werden Aufzeichnungen, Chats, Transkripte und Exporte separat berücksichtigt? |  |  |
| 11 | Können Meetings standardmäßig auf „nur eingeladene Personen“ begrenzt werden? |  |  |
| 12 | Gibt es eine Lobby oder vergleichbare Zutrittskontrolle? |  |  |
| 13 | Können Organisatoren Teilnehmende identifizieren, stummschalten und entfernen? |  |  |

| 15 | Sind öffentliche Links, Einwahl und Gastzugänge steuerbar? |  |  |
| 16 | Unterstützt der Dienst eine zentrale Anmeldung (SSO) mit der eigenen Identitätsverwaltung? |  |  |
| 17 | Sind starke Authentisierung und gegebenenfalls MFA für Administrationskonten möglich? |  |  |
| 18 | Gibt es einen nachvollziehbaren Prozess für Joiner, Mover und Leaver? |  |  |
| 19 | Können Aufzeichnungen standardmäßig deaktiviert oder rollenbasiert eingeschränkt werden? |  |  |
| 20 | Sind Aufbewahrungs- und Löschfristen je Datentyp konfigurierbar? |  |  |

| 22 | Gibt es Audit-Logs für Anmeldungen, Rollenänderungen und Aufzeichnungen? |  |  |
| 23 | Sind Sicherheitsvorfälle, Meldewege und Reaktionszeiten beschrieben? |  |  |
| 24 | Existiert ein Notfallkonzept für Ausfall, Kontenmissbrauch und Datenverlust? |  |  |
| 25 | Werden Updates, Schwachstellen und sicherheitsbezogene Änderungen kommuniziert und getestet? |  |  |

## So werten Sie die Ergebnisse aus

Addieren Sie nur die bewerteten Punkte. Bei 25 anwendbaren Kriterien sind maximal 50 Punkte möglich. Ein hoher Wert ersetzt keine Einzelprüfung: Eine **0** bei AVV, Drittlandübermittlung, Zugriffsschutz, Löschung oder Notfallvorsorge kann ein Ausschlusskriterium sein.

- **Grün:** Anforderungen und Nachweise sind vollständig; offene Punkte sind nicht kritisch.
- **Gelb:** Teilweise erfüllte Anforderungen oder fehlende Nachweise müssen vor der Entscheidung geklärt werden.
- **Rot:** Kritische Anforderungen sind nicht erfüllt oder Verantwortlichkeiten bleiben unklar. Einsatz erst nach Risikoentscheidung und dokumentierter Freigabe.

## Fünf Praxistests vor dem Einsatz

Dokumente allein zeigen nicht, ob eine Einstellung im Alltag funktioniert. Testen Sie daher:

1. ein Meeting mit externem Gast, Lobby und Rollenwechsel;
2. den sofortigen Zugriffsverlust eines ausgeschiedenen Kontos;
3. eine Testaufzeichnung samt Speicherort, Freigabe und Löschung;
4. Audit-Log und Sicherheitskontakt anhand eines Beispiels;
5. einen Ausfall mit dokumentiertem alternativem Kommunikationsweg.

Das [Sicherheitsangebot von Meetling](/sicherheit) kann als weiterer Prüfpunkt in die Anbieterbewertung einfließen. Wenn Sie Kriterien und Schutzbedarf gemeinsam strukturieren möchten, finden Sie unter [Beratung](/beratung) den passenden Kontakt. Aussagen über konkrete Produkte, Preise oder Zertifizierungen sollten Sie vor einer Entscheidung immer anhand aktueller Primärdokumente prüfen.

## Häufige Fragen

### Ist ein Serverstandort in Deutschland automatisch sicherer?

Nein. Der Standort ist nur ein Teil der Bewertung. Ebenso wichtig sind Zugriffsmöglichkeiten, Unterauftragnehmer, technische Schutzmaßnahmen, Vertragsgrundlagen, Löschprozesse und der tatsächliche Schutzbedarf.

### Reicht „verschlüsselt“ als Anbieterangabe?

Nein. Lassen Sie sich getrennt erklären, wie Übertragungen, gespeicherte Daten, Aufzeichnungen und Backups geschützt werden. Prüfen Sie außerdem Schlüsselverwaltung und den Geltungsbereich der Verschlüsselung. Eine Transportverschlüsselung ist nicht automatisch Ende-zu-Ende-Verschlüsselung.

### Muss jede Videokonferenzlösung SSO und MFA unterstützen?

Die Notwendigkeit hängt von Organisation, Schutzbedarf und Identitätskonzept ab. Für zentrale Konten und Administrationszugänge sind ein kontrollierter Lebenszyklus sowie starke Authentisierung häufig besonders wichtig. Die Entscheidung sollte begründet und dokumentiert werden.

### Was gehört in ein Notfallkonzept?

Mindestens Zuständigkeiten, Eskalationswege, alternative Kommunikationskanäle, Wiederanlauf und Umgang mit Kontenmissbrauch oder Datenverlust. Ein Plan ist erst belastbar, wenn er mit einem realistischen Szenario getestet wurde.
